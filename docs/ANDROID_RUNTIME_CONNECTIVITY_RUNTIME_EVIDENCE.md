## Interpretation Rules For Next Authorized Run

If listener is `127.0.0.1:8888`:

- Conclusion: runtime localhost-only.
- Next step: inspect `HttpServerManager` / Ktor startup path.

If listener is `0.0.0.0:8888` or `:::8888`, but external devices still time out:

- Conclusion: server broad-bind is working.
- Next focus: phone Wi-Fi IP, phone system inbound restrictions, VPN/network isolation, and whether the app displays the wrong IP.

If there is no `8888` listener:

- Conclusion: the service did not truly start, or started and exited.
- Next focus: logcat server start errors, watchdog behavior, foreground service exceptions, and package/runtime state.

If `ip addr` Wi-Fi IP and the app-displayed IP differ:

- Conclusion: `NetworkUtil` may be choosing the wrong interface.
- Next step: plan a minimal fix that prefers the WLAN interface.

If external access produces no server request log:

- Conclusion: the request is not reaching the app.
- Next focus: network path, listener address, IP selection, phone OS inbound restrictions, or LAN isolation.

If external access produces request logs but returns failure:

- Conclusion: the request reaches the app and fails inside routing/auth/handler logic.
- Next focus: token/auth, route handling, or endpoint behavior.
