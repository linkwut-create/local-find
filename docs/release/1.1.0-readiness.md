### 4.1 `testDebugUnitTest` 的 Gradle worker 环境缺陷（已定位根因，非代码问题）

`./gradlew testDebugUnitTest` 在本机上因 Gradle 自身的测试 worker 进程 classpath 传递机制失败：

```
Could not write standard input to Gradle Test Executor 1.
java.io.IOException: 管道正在被关闭。
...
Task :app:testDebugUnitTest FAILED
错误: 找不到或无法加载主类 worker.org.gradle.process.internal.worker.GradleWorkerMain
```

**根因**：本仓库路径含中文全角括号（`local-find（找手机app）`）。Gradle 在 Windows 上对超长
classpath（本项目实测约 43,754 字符，远超命令行长度上限）使用内部的 manifest-jar/参数文件
中转机制来启动测试 worker 子进程；这个中转机制在处理含非 ASCII 字符的路径时会损坏，
导致 worker 要么连自己的主类都找不到，要么加载到编译产物后再找不到 `DiscoveryEndpointPolicy`
等被测类。这与 `android/app/build.gradle.kts` 此前 keystore 路径必须改成相对路径的根因
（Java `.properties` 按 ISO-8859-1 读取非 ASCII 路径）是**同一类问题**，但这次卡在 Gradle
自身内部实现里，不是应用代码或 `build.gradle.kts` 能修的。已尝试的排查（均未解决 Gradle 侧）：

1. Git Bash `</dev/null` vs PowerShell 重定向 vs 完全前台无重定向——三种方式失败现象完全一致，
   排除是本次落地过程中的 shell/重定向副作用；
2. `--no-daemon` vs 默认 daemon 模式——现象一致；
3. 把 3.8GB 的 Gradle 用户目录从项目内的中文路径下（`android/.gradle-user-home`）复制到
   `D:\AIProjects\cache\lf-gradle` 短英文路径——**解决了依赖 jar 部分的 worker 启动失败**
   （不再是 `GradleWorkerMain` 找不到），但被测类和主代码类仍在 `android/app/build/...`
   （仍在含中文的仓库路径下），同一机制在这一步再次失败；
4. `JAVA_TOOL_OPTIONS=-Dsun.jnu.encoding=UTF-8`——无效，`sun.jnu.encoding` 在 Windows 上由
   进程启动时的系统 ANSI 代码页决定，JVM 启动后无法通过参数改写。

**真正能修的路径**（超出本次授权范围，未执行）：在 Windows 区域设置里开启
"Beta: 使用 Unicode UTF-8 提供全球语言支持"，或者把仓库整体迁移到纯 ASCII 路径。
前者是系统配置变更，后者是仓库路径迁移，任务包"不做"清单明确禁止改系统配置，
迁移仓库路径也超出本次任务范围，因此如实记录为 **BLOCKED**，不强行绕过。

**代码正确性的独立证明**：绕开 Gradle 测试 worker，直接用同一份编译产物 + 依赖 jar
通过原生 `java -cp ... org.junit.runner.JUnitCore` 运行同一个测试类，**9 个测试全部通过**，
证明失败完全在 Gradle 自身机制，与被测代码或测试代码的正确性无关。

## 6. 上传步骤（供用户参考；本会话不执行，也未做任何上传相关操作）

1. **若要上传到 Google Play**：先决定是否提升 `versionCode`（见第 1 节⚠️）。
   如果决定提升，改 `android/app/build.gradle.kts` 的 `versionCode`/`versionName`，
   重新执行 `bundleRelease`，再按 `docs/android16/PLAY_UPLOAD_RUNBOOK.md` 第 3 节的步骤操作
   （该文档记录的是 `versionCode 3` 首次上传时的真实步骤和坑，流程本身仍然有效）。
2. **若要发布 Chrome 扩展**：`local-find-release/local-find-chrome-extension-1.1.0.zip`
   已包含对齐后的 `manifest.json`（`version: 1.1.0`）和新增的 `net-utils.js`。
   上传前建议用 `chrome://extensions` 开发者模式先手动加载解压后的目录做一次冒烟测试
   （本会话未做，因为没有可用于扩展交互测试的浏览器自动化环境）。
   ⚠️ 该 zip 由 PowerShell `Compress-Archive` 生成，压缩包内路径分隔符是反斜杠
   （如 `icons\icon-128.png`），不是 ZIP 规范建议的正斜杠；多数工具能容忍，
   但如果 Chrome Web Store 上传时报格式问题，需要换用正斜杠的打包工具重新压缩。
