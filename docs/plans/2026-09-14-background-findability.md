# Local Find 后台/锁屏可找回引导计划

## 目标

让用户在手机锁屏、Local Find 退到后台时，仍能通过局域网找到手机；将必要的厂商后台设置明确呈现在应用内和安装文档中。

## 已知证据

- 测试机为魅族 Android 16；未加入电池白名单时，后台 `/ping` 连续请求为 `000/0`。
- 加入 `io.github.linkwutcreate.localfind` 的电池白名单并重新启动服务后，亮屏后台和锁屏各连续 4 次 `/ping` 均为 `HTTP 200`。
- 当前服务已有前台通知、唤醒锁和 Wi-Fi 锁；这些机制不能替代厂商的后台/自启动/防冻结设置。
- 本轮重新安装本地 Release APK 后，配对请求和控制端保存均成功；手机侧配对令牌存储在持久化 `SharedPreferences` 中，没有按天过期逻辑。
- 对服务做 force-stop 后重新打开 Activity，`/device-info` 仍然拒绝连接，界面显示“已停止”。当前 Activity 只绑定服务，不会在服务意外消失后重新启动它；Manifest 也没有开机/应用更新接收器。
- Chrome 扩展当前把配对时的 LAN IP 永久保存为设备地址。手机与电脑仍在同一网段时，若 DHCP 更换手机 IP，令牌仍然有效但旧地址不可达；扩展当前没有按设备 ID 重新发现地址的恢复路径。

## 实施范围

1. 保留现有“电池优化设置”入口，不新增可能影响发布合规的直接豁免权限。
2. 将中英文后台提示改为找手机所需的明确步骤：电池不优化、允许后台活动、开启自启动/启动管理、关闭后台冻结/清理，并保持锁屏 Wi-Fi。
3. 在安装/排障文档中同步同一套步骤，并注明修改设置后重新停止再启动服务。
4. 为“用户已选择保持可找”保存服务运行意图：Activity 再次打开时自动恢复前台服务；系统启动和应用更新时，在该意图仍为真时请求恢复；移除任务时尝试恢复。显式点击“停止服务”必须清除该意图。
5. 扩展在已配对设备连接失败且旧地址是私有 IPv4 时，只扫描旧地址所在 `/24`，以 `/device-info` 返回的持久设备 ID 校验目标并更新保存地址，然后重试原命令。只在已知设备的连接错误时触发，不能替代厂商网络隔离设置。

## 验收

- 静态：中英文 UI 字符串和安装文档都包含上述设置与重启步骤。
- 构建：Android Kotlin 编译通过。
- 设备：当前测试机保持已加入电池白名单、服务运行、手机解锁；后台/锁屏证据保留为本轮验证结果。
- 设备恢复：模拟服务被停止后，重新打开 Activity 能恢复 `/ping`；显式停止后重新打开 Activity 不应自动启动。
- 地址恢复：在同一 `/24` 内把保存地址替换为另一地址，扩展能按持久设备 ID找到当前手机并成功重试一次受保护命令。
- 锁屏控制：服务恢复后，手机锁屏时 Chrome Canary 控制端仍能完成命令和停止命令。
- 未覆盖：Android/OEM 的强制停止、后台冻结、用户关闭自启动、网络 AP 客户端隔离仍不能由应用保证；这些情况必须明确显示为环境边界，而不是配对失败。

## 回滚

只回滚本计划新增的 UI、生命周期、地址恢复和文档改动；不移除测试机电池白名单，除非用户另行要求恢复原系统设置。测试 APK 可用同一签名的上一构建覆盖安装，配对数据不应因覆盖安装被清除。
